# HTML named character references

`akashic/markup/html-entities.f` holds the 2,125 named character references
the WHATWG HTML standard lists with a semicolon, such as `&amp;`, `&nbsp;`
and `&NotEqualTilde;`. The standard says that list will not change.

```forth
REQUIRE markup/html-entities.f

name-a name-u HENT-LOOKUP   ( -- cp1 cp2 n )
```

`HENT-LOOKUP` takes a name without its `&` and `;`. Names are
case-sensitive, so `AMP` and `amp` both exist but `aMP` does not. It returns
the one or two scalars the reference stands for, with `n` set to 1 or 2.
`cp2` is 0 unless `n` is 2. A name the list does not have returns `0 0 0`.
93 references stand for two scalars, such as `&acE;` (U+223E U+0333).

The file is generated by `local_testing/generate_html_entities.py` from
Python's `html.entities.html5`, which is the WHATWG list. The generator pins
the list's size and SHA-256, so a Python with a different list cannot produce
a different table unnoticed. `--check` proves the checked-in file is current.
Never edit the file by hand.

The references are kept as one text of `name=hex` or `name=hex,hex`
entries, sorted by name and separated by spaces: 26,666 bytes. At load time
the module builds an index of where each entry starts, four bytes an entry,
and a lookup searches the names in halves. Loading the file costs about 5.9
million guest steps. Every word only reads the text and the index, so
lookups are reentrant and need no guard.

The partial tables in `markup/core.f`, `markup/html.f` and
`markup/readable-text.f` predate it.
