# akashic-p256 — NIST P-256 Point and Key Primitives

`p256.f` is the generic NIST P-256 curve layer used below JOSE and other
protocol libraries. It owns no key or mutable operation state. Public inputs
and outputs use protocol byte order; the Field ALU representation remains
inside caller-owned scratch.

```forth
REQUIRE akashic/math/p256.f
```

`PROVIDED akashic-p256` — requires `math/field.f`, `math/entropy.f`, and
the neutral `utils/memory-span.f` and `utils/caller-span.f` boundaries.

## Encodings and sizes

```forth
P256-PRIVATE-SIZE    ( -- 32 )
P256-SCALAR-SIZE     ( -- 32 )
P256-PUBLIC-SIZE     ( -- 65 )
P256-WORKSPACE-SIZE  ( -- 1152 )
P256-RESERVED-OVERLAP? ( address length -- flag )
```

Private and public-operation scalars are 32-byte unsigned big-endian values.
A private scalar is valid only in `1..n-1`. The two public scalars accepted by
the linear-combination operation may be zero but must be less than `n`.

Public keys use the uncompressed SEC 1 encoding:

```text
0x04 || X[32] || Y[32]
```

Compressed points, the point at infinity, noncanonical coordinates, and
off-curve points are not public encodings of this API.

`P256-RESERVED-OVERLAP?` reports whether a borrowed span intersects the
complete lower-layer footprint that a checked consumer must not alias:
crypto-ACC ownership/scrub state, Field guard/tables/scratch, or the five
private P-256 constant tables. It only compares address geometry. It does
not allocate memory, retain the span, establish a lifetime, or prove that
the caller owns the allocation.

## Operations

```forth
P256-KEYGEN
  ( private-output public-output workspace -- status )

P256-PUBLIC-FROM-PRIVATE
  ( private public-output workspace -- status )

P256-PUBLIC-VALID?
  ( public workspace -- valid? status )

P256-PUBLIC-SCALAR-LINCOMB
  ( scalar-g scalar-q public-q result workspace -- status )

P256-WORKSPACE-CLEAR
  ( workspace -- status )
```

`P256-KEYGEN` obtains unbiased candidates only through `ENTROPY-FILL`. Its
rejection loop is bounded to 16 candidates. The private and public outputs
are fully staged before the final publication phase begins. The private and
public buffers are copied separately; this is not a crash-atomic grouped
update.

`P256-PUBLIC-FROM-PRIVATE` validates the private scalar and derives
`private*G`. The 65-byte public output is staged until completion.

`P256-PUBLIC-VALID?` is a predicate: a well-shaped but malformed or off-curve
encoding returns `0 P256-S-OK`. A nonzero status reports an inability to
perform the check, not an ordinary invalid key.

`P256-PUBLIC-SCALAR-LINCOMB` computes:

```text
scalar-g * G + scalar-q * public-q
```

It is the public-scalar verification primitive used by ECDSA. If the valid
combination is the identity, no SEC 1 result can be published and the
operation returns `P256-S-IDENTITY`.

## Ownership and timing

Every fixed-width input, output, and workspace first passes
`CALLER-SPAN-STATUS`, then `P256-RESERVED-OVERLAP?`, before pairwise alias
checks and before any workspace byte changes. Physical admission requires the
whole fixed span to fit in one mapped memory window and rejects
BIOS/private/live-stack storage. It is a protection and geometry check, not
an allocation-ownership proof. The caller must still own the workspace
exclusively from entry through return; sharing it with another task or nested
operation violates the contract. Borrowed private scalars, public scalars,
and public keys must remain immutable for that interval.

Every returned geometry, key, scalar, entropy, or internal failure leaves
published outputs unchanged. Once a workspace is admitted, clearing is
attempted after success, ordinary rejection, or unexpected `THROW`.
Unexpected operation faults are caught only long enough to attempt that
wipe, then rethrown unchanged. A wipe fault also propagates because cleanup
completion is ambiguous; it is never normalized to `P256-S-INTERNAL`.

Staging gives each output a final in-process commit point: normal computation
and ordinary rejection do not modify it before the final `MOVE`. It does not
make ordinary memory power-failure or fault atomic. In particular, key
generation publishes two separate caller buffers, and a fault during either
final copy may expose a partial write. Such a publication fault is rethrown
after the workspace-wipe attempt rather than converted into a status whose
usual nonpublication guarantee would be false.

Each scalar multiplication executes exactly 256 rounds. Every round computes
both candidate paths and selects bytewise without a secret-dependent branch
or table lookup. The complete public operation owns the recursive Field
transaction across prime selection, point arithmetic, and affine conversion;
that transaction serializes the shared Field ALU and cryptographic
accumulators.

## Status values

| Status | Meaning |
|---|---|
| `P256-S-OK` | The operation completed; consult `valid?` where present. |
| `P256-S-RANGE` | A complete fixed caller span is null, signed, wrapping, outside one mapped window, or crosses a window. |
| `P256-S-PROTECTED` | A fixed caller span intersects BIOS/private/live-stack storage. |
| `P256-S-PLATFORM` | Caller-memory qualification failed unexpectedly or returned an undocumented platform result. |
| `P256-S-ALIAS` | Public operands overlap each other or the complete P-256/Field/crypto-ACC reserved footprint. |
| `P256-S-PRIVATE` | A private scalar is zero or not less than `n`. |
| `P256-S-PUBLIC` | A required public point is malformed, noncanonical, or off-curve. |
| `P256-S-SCALAR` | A public linear-combination scalar is not less than `n`. |
| `P256-S-IDENTITY` | A valid linear combination produced the point at infinity. |
| `P256-S-ENTROPY` | Checked entropy was unavailable during key generation. |
| `P256-S-INTERNAL` | A bounded retry exhausted or a subordinate result was impossible. |

`P256-STATUS-VALID?` validates this status vocabulary.
