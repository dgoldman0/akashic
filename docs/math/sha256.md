# akashic-sha256 — Checked Hardware SHA-256

`math/sha256.f` is the Akashic one-shot boundary for the Megapad-64 BIOS
SHA-256 engine. Compression, padding, context storage, output staging, and
context erasure are implemented by the chip and its checked BIOS ABI; the
library adds public span policy, operation ownership, status normalization,
and digest utilities.

```forth
REQUIRE math/sha256.f
```

## API

```forth
SHA256-LEN           ( -- 32 )
SHA256-HEX-LEN       ( -- 64 )
SHA256-STATUS-VALID? ( status -- flag )
SHA256-CALLER-SPAN-STATUS
  ( address length -- status )

SHA256-HASH
  ( src len dst -- status )

SHA256-HASH-2
  ( a1 u1 a2 u2 dst -- status )

SHA256-HASH-3
  ( a1 u1 a2 u2 a3 u3 dst -- status )

SHA256->HEX     ( digest destination -- 64 )
SHA256-.        ( digest -- )
SHA256-COMPARE  ( first second -- equal? )
```

The multi-span forms hash the exact byte concatenation without requiring a
temporary concatenation buffer. Input spans may overlap one another.

There is intentionally no public INIT/UPDATE/FINAL or begin/add/end surface.
A caller-spanning stream would expose ambient accelerator state across
arbitrary work and make exception-safe ownership impossible to guarantee.

`SHA256-CALLER-SPAN-STATUS` is the reusable, nonmutating caller-memory
boundary. It returns `0`/`OK` for an empty or admitted span, `2`/`RANGE`
when the complete span is not inside one BIOS-advertised physical window,
`3`/`ALIAS` for the SHA-256 guard, shared crypto-ACC storage, or either
algorithm's complete all-core BIOS context arena, and `5`/`INVALID` for
negative, null nonempty, or wrapping geometry. A caught exception or an
undocumented BIOS result is normalized to `6`/`CRYPTO`; this word never
returns `STATE` or `LENGTH-OVERFLOW`.

## Status values

| Status | Meaning |
|---|---|
| `SHA256-S-OK` | The 32-byte digest was published. |
| `SHA256-S-STATE` | The checked BIOS context was not in the required state. |
| `SHA256-S-RANGE` | A span is outside one BIOS-advertised physical window. |
| `SHA256-S-ALIAS` | An input/output pair or caller span/reserved crypto region overlaps, or a BIOS context arena was addressed. |
| `SHA256-S-LENGTH-OVERFLOW` | The SHA-256 bit-length calculation overflowed. |
| `SHA256-S-INVALID` | Public geometry is negative, null when nonempty, or wrapping. |
| `SHA256-S-CRYPTO` | An unexpected pre-publication exception or invalid BIOS status occurred. |

`SHA256-STATUS-VALID?` accepts exactly the inclusive range from
`SHA256-S-OK` through `SHA256-S-CRYPTO`.

Every returned nonzero hash status leaves all 32 destination bytes
unchanged. Before claiming either crypto resource or issuing `SHA256-INIT`,
the library applies `SHA256-CALLER-SPAN-STATUS` to every input and to the
fixed-size destination, then checks input/output overlap. A zero-length
input is valid and may use address zero; a nonempty input and the destination
must be nonnull and nonwrapping. The pure BIOS qualification includes the
calling core's currently active context, so even that alias returns before
INIT without disturbing the live context. The local guard and crypto-ACC
regions are also rejected before acquisition because acquisition or cleanup
would mutate them.

## Ownership and cleanup

An admitted operation uses this fixed order:

```text
CRYPTO-ACC transaction
  -> SHA-256 blocking operation guard
    -> BIOS SHA256-INIT
    -> BIOS SHA256-UPDATE (one to three times)
    -> BIOS SHA256-FINAL
```

The outer transaction protects ACC0–ACC3 from Field-ALU interference. The
algorithm guard keeps one logical hash intact across task switches. BIOS
UPDATE and FINAL defensively repeat physical-window and hidden-context
checks before reading or publishing caller memory.

Any admitted failure before successful publication invokes the idempotent
`SHA256-CLEAR` operation while both ownership scopes are held. Successful
FINAL already erases and releases the BIOS context, so the library does not
issue a redundant post-success CLEAR.

INIT and UPDATE execute behind a pre-publication `CATCH`; an unexpected
exception there is safely normalized to `SHA256-S-CRYPTO`. FINAL has a
separate exception boundary. Forth `CATCH` cannot reveal whether a throwing
FINAL published before throwing, so that exceptional path performs CLEAR
and releases the SHA guard, then rethrows. It is deliberately not converted
into a returned failure whose unchanged-destination guarantee could not be
proved. The outer crypto transaction likewise releases on the propagated
exception.

## Digest utilities

`SHA256->HEX` writes 64 lowercase hexadecimal characters and returns 64.
`SHA256-.` prints the same representation. `SHA256-COMPARE` scans all 32
bytes and OR-accumulates differences, returning true only when the digests
match.

```forth
CREATE message 3 ALLOT
97 message C!  98 message 1+ C!  99 message 2 + C!
CREATE digest SHA256-LEN ALLOT

message 3 digest SHA256-HASH
DUP IF
    \ digest was not changed
    THROW
THEN
DROP
digest SHA256-.  \ ba7816bf...
```
